# Governed skill authoring

A skill makes a stochastic agent follow a predictable process. Author it as versioned harness code under a locked capability-work requirement.

1. Choose explicit user-only or model invocation. Completion: the policy is represented natively in every supported harness; unsupported is proven, and no renderer falls back to a different harness.
2. Write one narrow description branch per genuine trigger and register positive plus negative invocation evals. Completion: broad synonyms, duplicate branches, and missing trigger evidence are absent.
3. Order the process and give every step a checkable, exhaustive completion criterion. Completion: premature closure cannot satisfy the contract.
4. Keep each rule in one source of truth. Disclose branch-specific reference behind precise context pointers; keep universally required steps inline. Completion: references resolve and no load-bearing rule is duplicated.
5. Bind typed input/output artifacts, authority, tools, paths, redaction, interruption state, stale/malformed rejection, and forward-only recovery. Completion: the skill can resume without treating chat or prose as authority.
6. Register, independently validate, render native assets, and execute a real artifact producer-to-carrier-to-consumer witness. Completion: creating a file alone cannot close the capability.
7. Record version, changelog, semantic review, provenance, and evidence. Completion: adapted content has manifest-covered attribution and generated notices.

Prune sediment, duplication, sprawl, and no-op wording. Use strong shared vocabulary to anchor invocation and execution. Prefer positive target behavior; retain hard prohibitions where safety, authority, or evidence would otherwise fail open.

A repairable authoring miss stays in the current capability-factory run: resolve the gap, apply the exact amendment, invalidate affected evals/assets, rerender, and resume. A hard external limit remains pending-live or unsupported with an exact next action.
